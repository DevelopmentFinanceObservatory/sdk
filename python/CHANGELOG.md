# Changelog

All notable changes to this package are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this package adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `dfo.search`, `Client.search` and `AsyncClient.search` take publisher series codes in place of a question: `dfo.search(codes=["DT.TDS.MLAT.CD", "DT.TDS.BLAT.CD"], entities={"destination": ["country/KEN"]}, window=(2015, 2023))`. Each code is its own part of the answer. `variable` gives words that choose among a code's variables and defaults to the code itself. `entities` and `window` take the forms `fetch` takes, `open_roles` takes `origin` or `destination` to answer member by member, and `source` names the source in words, such as `"IDS"`, for a code two sources hold. A question beside any of these keywords, a keyword without `codes`, codes passed as the question, a role bound to no entity, or `codes` given as one string or naming a code twice raises `InvalidRequestError` (`invalid_argument`) before any request. `entities` binds each role to a list, a tuple or a one-shot iterator such as a generator, in `search` and `fetch` alike, and a role bound to a set, a map or a map's view, whose order is not fixed, raises `InvalidRequestError` (`invalid_argument`). The client sets no cap on codes or entities. A server refusal arrives as `request_invalid`.
- An answer flags a part asked by a series code whose reading is not that code's series alone: every code in the spec's `resolved.stat_vars.source_codes` must be the asked code with `exact` true. Such a part keeps its reading and becomes a gap of kind `no_data` whose message names the asked code and the codes the reading holds, and says to narrow the search with `variable=` or `source=`, or to fetch the reading as it is with `dfo.fetch(answer.parts[i].spec)`. `answer.fetch()` raises `IncompleteAnswerError` (`answer_incomplete`), `answer.fetch(partial=True)` builds the other parts, and `answer.choose` posts the part back by its restatement. In an answer to a search by codes, the code each part asked decides, whatever the part's restatement names or leaves out. `answer.to_json()` writes such an answer at `format_version` 2, with those codes in a top-level `codes` member, one per part in part order, and `Answer.from_json` reads them, so an answer read back has the gaps the live answer had. An answer to a question in words stays at `format_version` 1. `answer.choose` keeps them too, so the new answer checks each part against its code again, and a reply to the choice with another number of parts than codes raises `ContractError` (`contract_violation`). `from_json` reads `codes` as `search(codes=...)` reads them, and raises `FormatError` (`format_invalid`) at `/codes` for codes `search` refuses, such as a blank code or one code twice, for a count other than the parts, for `codes` at format 1, and for format 2 without them. 0.2.0 refuses format 2 as "not 1". Both clients trim a code of the white space JavaScript's `trim` removes, so a code reads the same in each. An answer to a question in words writes no `codes` and reads a part's code from its restatement, so the check holds for a code Search found in the question's words. A code part whose spec has no `resolved.stat_vars` is a gap too. Answer JSON written by 0.2.0 holds none, so a 0.2.0 saved answer whose question named a series code reads back with a gap on that part, and fetching it needs a fresh search. An incomplete answer whose every part names a series code counts series codes: "Answered 2 of 3 series codes."
- `data.provenance` is a `dfo.Provenance`, a frozen record of where a Dataset came from: its sentence, citation, `fetched_at`, question, `pinned`, `held_until`, warnings, `complete`, `missing` and members, each with its spec id, version, digest, parts, sentence, citation and retention, and `ref`, the `DatasetRef` the members name. `to_json()` gives it as JSON text in the format `provenance.schema.json` in the client contract gives, and `Provenance.from_json(value)` reads a record either client wrote, from its JSON text, as str or bytes, or the object `json.loads` gives, so `Path(path).write_text(data.provenance.to_json())` stores it. Two records are equal under `==` when they hold the same facts. A key the format does not name, at the top level, in a member, in a citation or its sources, in a warning, or in a missing part or its options, is ignored, so a record a later client adds a key to still reads. The ref keeps its own format. The record's and the Dataset's `pinned` and `held_until` come from the members' retention. `complete` and `missing` are the dataset's, each missing part as the saved file holds it, so a partial dataset's record differs from a complete one's. `dfo.load` refuses a saved file whose `dfo.dataset` has `complete` true beside a missing part, as the record's reader does, with `format_invalid` at `/dfo.dataset/complete`. A record that breaks the format, comes from a later `format_version`, has members that differ from the members its ref names, or a `pinned` or `held_until` other than what its members give, a record with no member included, or a `complete` that is true beside a missing part, raises `FormatError` (`format_invalid`) at a JSON Pointer, and a ref that breaks its own format raises as `DatasetRef.from_json` does, under `/ref`. A derived Dataset's provenance names its derived members. `data.save` writes the same facts from the same record, so the provenance of a Dataset `dfo.load` read equals the provenance of the Dataset that saved it.
- Each of `data.members` holds its version's retention, `pinned` and `held_until`, as its manifest serves it, each None when the server does not say. `data.pinned` and `data.held_until` keep their meaning and derive from the members' values. A dataset is pinned when every member is, and held until the earliest date of the members not pinned. `dfo.pin(data)` returns a Dataset whose members are all pinned. `data.save` writes the members' retention under a new top-level key, `dfo.retention`, which 0.2.0 ignores. A file without it, as one 0.2.0 saved, loads every member as pinned when the file says the dataset is, and otherwise with `pinned` None, unknown, and the file's `held_until`. A file whose `pinned` or `held_until` is other than what its members give, a file with no member included, raises `FormatError` (`format_invalid`).
- `dfo.file_url(member)`, `Client.file_url` and `AsyncClient.file_url` return a link to a pinned member's file that a pipeline can commit and read with any HTTP client and no key. The member is one of `data.members` or `data.ref.members`. The URL names the file selector, `/datasets/{spec_id}/{content_version}/file`, under the client's base URL, with the query of the rendering the member was built in, so it serves the same table. The call reads the version's manifest once. A version that is not pinned raises the new `dfo.errors.VersionNotPinnedError` (`version_not_pinned`), an `InvalidRequestError` whose `held_until` attribute is the date DFO stops guaranteeing the version and whose message says to run `dfo.pin(data)` first. A member of a derived Dataset raises `InvalidRequestError` (`invalid_argument`) before any request.

### Changed

- The `pyarrow` floor is `>=19.0.1`, down from `>=21`, so the package installs beside packages that pin an older pyarrow, such as `bblocks-data-importers`. pyarrow 19.0.0 cannot read the Parquet files the server returns, and 18 and older fail to stack struct columns with differing fields.
- `dfo.lookup.error_code` and `client.lookup.error_code` replace `lookup.code` for the registry entry of one of DFO's own error or warning codes, so the name no longer reads as a lookup of a publisher's codes. `lookup.code` stays as a deprecated alias that returns the same `Code` and issues a `DfoDeprecationWarning` (`name_deprecated`) at the caller's line naming `lookup.error_code` and 0.4.0, the release that removes it.
- `answer.to_json()` keeps each spec's `resolved.stat_vars.source_codes`, which the exact-code check reads.
- An answer counts and builds only the parts without a gap: `answer.specs` and `answer.fetch(partial=True)` leave out a definite part that is a gap, and the printed answer counts it as missing.

### Fixed

- A redirect whose `Location` does not resolve to an http or https URL with a host, such as a `javascript:` or `ftp:` URL, raises `ContractError` (`unexpected_response`). Under httpx2 2.16.2 such a redirect reached the caller.

## [0.2.0] - 2026-11-14

### Added

- `data.party_totals_left_out` names the group totals a fetch left out of each member, as `dfo.types.PartyTotalsLeftOut` entries of spec id, party role, dcids, provenance and `kept_in`, the series whose rows kept those totals, each a `dfo.types.KeptSeries` of the series' cells and the periods in which it kept them. `role_key` names the `entities=` key of the entry's column, `origin` or `destination`, or None for a column the client does not know. The repr counts the totals on each role with its role key, as `15 on financingProvider (origin)`. Entries keep the manifest's order, and two can share a role and a provenance. `data.save` writes them under a new `dfo.party_totals_left_out` key, with `kept_in` where an entry holds it, which 0.1.0 ignores, and `dfo.load` reads a file without it.
- A derived Dataset reports the party totals each reading's read left out, from the derived manifest's `roots[].party_totals_left_out`, each entry named by the reading's spec id in the order of the ref's roots, and its repr's line reads `Party totals left out of the readings`. The report is empty against a server older than it and when DFO could not read a reading.
- `docs/datasets.md` says when the default keeps a total. A role the spec binds keeps what it binds. On an open role the cut judges each series, the frame's columns other than the role, `time_period` and provenance, in each period: a period with single parties drops its totals, a period of only totals keeps its whole ones, and with none whole it drops them when the series has single parties in another period and keeps them otherwise.
- `entities=` on `fetch` and `answer.fetch` takes the `Match` and `Entity` objects `dfo.lookup.resolve` returns beside dcids, as in `entities={"destination": dfo.lookup.resolve("Nigeria")}`. A match that is not `resolved` raises `InvalidRequestError` (`match_unresolved`) before any request, printing the match and a candidate to pass instead. An awaitable in its place, such as `client.lookup.resolve(...)` on an `AsyncClient` without `await`, raises the same error and names the missing `await`.
- `docs/settings.md` lists every client option and environment variable with its default and which source wins.
- `data.to_bytes()` returns the Parquet file `data.save(path)` writes, and `dfo.load` reads those bytes, or any bytes-like object such as a `bytearray` or `memoryview`, as it reads a path.
- `data.from_cache` says whether a fetch read any member's file from the cache, and `data.fetched_at` when the data left the server, in UTC. The repr adds `Cached: read from the cache, fetched <time>` on a cache hit online, and the `Stale:` line under `DFO_OFFLINE=1` ends with the same time. The cache records each download's time under `fetched/sha256/<hex>`. A file 0.1.0 stored has none, and the repr says `fetch time unknown`. Eviction counts each time's bytes against the cache's size limit, removes it with its file, and removes a time whose file is gone.
- `data.question` holds the question of the answer a dataset was fetched from. `data.save` writes it under `dfo.question` and the fetch time under `dfo.fetched_at`, each a JSON string, and leaves out either key when it has no value. 0.1.0 ignores both keys, and `dfo.load` reads a file without them.
- `DFO_TIMEOUT`, in seconds, and `DFO_MAX_RETRIES` set `timeout` and `max_retries` for a `Client`, `AsyncClient` or `dfo.configure` built without them. An argument wins over the variable, and `timeout=None` leaves `DFO_TIMEOUT` unread so each call keeps its own default. A `DFO_TIMEOUT` other than digits with an optional fraction above 0, such as `300` or `2.5`, or a `DFO_MAX_RETRIES` other than digits from 0 to 10, raises `InvalidRequestError` (`invalid_argument`) when the client is built, naming the variable; the client behind `dfo.search` and `dfo.fetch` raises it at the first call, and `import dfo` reads neither. `dfo.types.FROM_ENVIRONMENT` is the default of both arguments, typed by `ClientTimeoutArgument` and `MaxRetriesArgument`.
- `dfo.types.CLIENT_TIMEOUT` is the default of every call's `timeout` and stands for the client's `timeout`, and `dfo.types.CallTimeout` types the argument, so a function that wraps a call can pass the default on.

### Changed

- A fetch posts the party-totals cut, its default, as `party_totals: false` in the build request's `options`, the spelling DFO's API takes from dfo-apis 133262c5e on, in place of `without_party_totals: true`. Release 0.2.0 needs a server that accepts `options.party_totals`, and the release workflow checks that production does before it publishes. A ref and a served rendering read in either spelling, and `data.ref` still writes `without_party_totals: true`, so 0.1.0 reads a ref this release writes. The client follows the API contract at spec-kit 7ef7f71.
- A citation source's licence reads from the served `licence` and `licence_url`, falling back to `license` and `license_url` when the response lacks them, as a response from a server before the rename does.
- A fetch reads `trace.party_totals_left_out` leniently. A trace that is no object or a member that is no list names no totals, and a malformed entry, such as one with an empty `role`, entity or period or a `kept_in` out of the contract's order, is dropped while the entries beside it still read. A manifest with a broken trace no longer raises `ContractError`.
- `dfo.load` refuses a file whose `dfo.format_version` disagrees with its `dfo.ref` (`2` exactly when the ref holds a derived member, `1` otherwise), a `dfo.party_totals_left_out` entry that names neither a dataset member of `dfo.ref` nor a root of a derived member, such as the derived member's own id, or lists them out of member then root order, and an entry with an empty `role`, entity or period or whose `kept_in` breaks the contract's shape or order, each as `FormatError` (`format_invalid`).
- `development-finance` installs beside any `httpx2` and `httpcore2` from 2.15 on. The transport builds its connection pools through their public interfaces, so a new minor release of either needs no new client release.
- `development-finance` needs `pyarrow>=21`, the first release whose `concat_tables` stacks members whose struct columns differ by field name, order or type.
- The `polars` extra needs `polars>=1.3`, the first release whose `DataFrame` reads a `Dataset` through the Arrow stream. A CI job installs every floor and runs the suite.
- **Breaking:** `timeout` on `Client`, `AsyncClient`, `dfo.configure` and `with_options` bounds each whole call, retries, waits and downloads included, for every call that passes no `timeout` of its own, and defaults to None, which leaves `search` at 60 seconds and `fetch` and `dfo.analysis` waiting as long as the server takes. The bound on one request attempt, which `timeout` set in 0.1.0, is the new `attempt_timeout`, 30 seconds by default. `Client(timeout=60)` from 0.1.0 code now stops each call after 60 seconds with `DfoTimeoutError` (`deadline_exceeded`). Pass `attempt_timeout=60` for the old meaning. A call's `timeout=None` still waits without a bound, and a timeout's message names the option that ran out.
- **Breaking:** `with_options(timeout=None)` returns a copy with no client bound on its calls, so each call keeps its own default. In 0.1.0 it kept the client's `timeout`. Leave `timeout` out to keep it now.
- **Breaking:** `Client.fetch`, `AsyncClient.fetch` and `dfo.fetch` carry one overload per target, so a type checker rejects an option the target ignores: `window`, `entities`, `facets`, `layout` and `party_totals` go with a `Spec` only, `latest` with a `DatasetRef` or `Recipe`, `progress` with anything but a `Recipe`, and `as_of` and `slot` with a share. A last overload takes a target typed as the union of all four with the options every target takes, `strict` and `timeout`. The run-time checks stay.
- **Breaking:** the platform default cache root is `dfo` in place of `readerkit`: `~/.cache/dfo` on Linux (or `$XDG_CACHE_HOME/dfo`), `~/Library/Caches/dfo` on macOS, and `%LOCALAPPDATA%\dfo\Cache` on Windows. With no `cache_dir`, `DFO_CACHE_DIR` or `BBLOCKS_CACHE_DIR`, a file or manifest missing from the cache is read from the same path under the 0.1 `readerkit` root when it passes the checks a cached entry passes, and copied in without a fetch time, so an offline fetch of something 0.1 downloaded still loads. The client never writes, evicts or clears the `readerkit` directory, and `dfo cache clear` empties the `dfo` one only.
- **Breaking:** error messages end with `[<code> trace=<id>]`, or `[<code>]` with no trace id, in place of `[<code> · trace <id>]`. The bracket text can change in any release. `error.code` and `error.trace_id` are the stable fields.
- **Breaking:** `dfo.errors.FormatError` and `dfo.errors.BundleError` derive from `DfoError` as well as `ValueError`, so `except DfoError` around `dfo.load(path)` catches them. Their `code` equals `reason`, which names the fault. `dfo.load` of a saved file from a later format version raises `FormatError` at `/dfo.format_version`.
- **Breaking:** calls that raised a bare `ValueError` or `TypeError` for bad input raise a `DfoError` subclass with a client code, which is still a `ValueError` or `TypeError` where it was one, so `except ValueError` and `except TypeError` keep catching it. `DatasetRef(...)` with a member of the wrong kind (also a `TypeError`) or of mixed kinds, and `BundleLimits` with a limit that is not a positive integer, raise `InvalidRequestError` (`invalid_argument`); `data.ref` on a bundle opened from a folder raises it with `ref_unavailable`, and a proxy URL whose scheme is not http, https, socks5 or socks5h with `proxy_invalid`; `ApiKey("")` raises `AuthenticationError` (`key_empty`), and `ApiKey` of a non-string (also a `TypeError`) or a key the credentials file cannot store raises it with `key_invalid`; `dfo.auth.login()` with no key raises `AuthenticationError` (`key_empty`), and over a broken credentials file with `credentials_file_invalid`; `RawResponse.json()` on a body that is not JSON raises `ContractError` (`unexpected_response`).

### Removed

- **Breaking:** `Answer.choose` takes no second positional argument. The earlier `choose(part, option)` form now fails as any call with too many arguments does. Pass `choose(option, part=part)`.

### Fixed

- `dfo.load` of a damaged Parquet file or ZIP raises `BundleError` (`not_a_bundle`), and of a bundle whose XLSX is damaged `FormatError`, each with pyarrow's or `zipfile`'s error as its cause. Both used to escape as pyarrow and `zipfile` errors. A read that fails at the disk, such as `EIO`, still raises its own `OSError`.
- `answer.timed_out` is true when a part's own no-data reason is `timed_out`, as well as when Search's diagnostics say so, and `Answer.from_json` works it out again.

## [0.1.0] - 2026-11-13

The first release of `development-finance`, the Python client for the Development Finance Observatory APIs. It imports as `dfo` and runs on Python 3.12 or later.

### Added

- `dfo.search(question)` returns an `Answer` that prints what Search understood and the line to type next. `answer.choose(option, part=...)` settles a part that awaits a choice, by index or label.
- `answer.fetch()` and `dfo.fetch(spec)` return a `Dataset`. A long build shows progress and waits as long as the build takes unless `timeout=` is set. A fetch that is interrupted or times out leaves the build running, and the same fetch joins it.
- `dfo.fetch(spec)` narrows a reading on the server with `window`, `entities` and `facets`, `entities` keyed by role as `place`, `origin` or `destination`, and `answer.fetch` narrows every reading of an answer with them. `layout="frame"` returns one reading's pipeline frame.
- Datasets leave out party totals, such as the DAC total beside its members, unless `party_totals=True`, and put the reading columns first, then the columns that vary between rows, then the constant ones, with `stat_var` last. Rows sort so that each series reads in time order. Two cells hold the same value when they are equal as values: 0.0 and -0.0 are one value, as are any two NaNs, a list cell matches another item by item in order, and a struct cell field by field in any order. A list or struct column is no sort key, and a column of any other nesting, such as a map, raises `ContractError` (`contract_violation`).
- `data.to_pandas()`, `data.to_polars()` and `data.to_arrow()` convert a dataset, with pandas and polars as optional extras. `data.save(path)` writes a Parquet file that `dfo.load(path)` reads back.
- `data.ref` names the exact versions a dataset holds. `dfo.fetch(data.ref)` reads them again, and `dfo.fetch(data.ref, latest=True)` builds the newest. `ref.to_json()` and `DatasetRef.from_json(text)` carry a ref as JSON that the TypeScript client also reads. When a ref's file has expired or is no longer listed, the fetch asks the version's file selector for its `format`, `bundle` and `layout`, then builds the version again.
- `answer.to_json()` and `Answer.from_json(text)` save an answer and restore it.
- `dfo.lookup` resolves names to graph nodes, reads a node or a code's registry entry, and lists what Search holds data on. Each returns a small type from `dfo.types` that prints one line, such as `Germny -> not found; nearest: Germany  country/DEU`, and keeps the server's JSON as `raw`.
- `Client` and `AsyncClient` carry the same calls for one configuration each: `api_key`, `base_url`, `headers`, `header_provider`, `timeout`, `max_retries` and the cache. `dfo.configure` sets the client the module functions use.
- Every request to the API carries `X-DFO-Client`, such as `dfo-python/0.1.0 (CPython 3.14)`. A `headers` or `header_provider` entry that names it raises `InvalidRequestError` with `header_invalid`.
- The client works without a key under a per-IP quota. `dfo auth login` stores a key in a credentials file every DFO client reads, and `dfo auth status` prints the key the client sends, masked, and where its requests go. `DFO_API_KEY`, `DFO_PROFILE` and `DFO_BASE_URL` configure the client from the environment. A base URL is an absolute http or https URL with no userinfo, query, fragment, dot segment or backslash, whose port, when it names one, is 1 to 65535; any other raises `InvalidRequestError` with `base_url_invalid`.
- Downloads are cached on disk, verified against their digest, and readable offline with `DFO_OFFLINE=1`. `dfo cache clear` empties the cache.
- Errors live in `dfo.errors`, one class per next step, and each message ends with its code, and with the trace id when there is one. The client retries failures that can clear, honouring `Retry-After`.
- `dfo.types` holds the types of what answers and datasets contain. The package ships `py.typed`.
- `dfo.analysis` runs DFO's operations on the server and returns a derived `Dataset`: `filter`, `aggregate`, `growth`, `rank`, `quotient_of`, `share_of`, `join`, `sum_of` and `compare`, each with `strict` and `timeout`, and on `client.analysis`. `growth(change="relative")` is a fraction where 0.25 is a 25% rise and `change="difference"` is in the data's unit, and `share_of` is a percentage.
- `dfo.analysis.recipe(start)` describes a chain of operations without running it, and `dfo.fetch(recipe)` runs it in one request. `dfo.latest_year(offset)` names a year DFO settles each run. `dfo.fetch(ref)` reads a derived ref, and `dfo.fetch(ref, latest=True)` computes it again on the newest data.
- `Dataset.left_out` lists the series an operation dropped for missing data, with the step and the reason, and `SeriesLeftOutWarning` (`series_left_out`) says so once per fetch, raised under `strict=True`. A derived dataset's repr names its steps, the period `latest_year` settled on, and the count of series left out, and `data.save` keeps the steps and the list. A saved derived dataset declares format version 2, which a client that reads format 1 alone refuses as a later format, and a dataset of dataset versions still saves format 1. `isinstance(member, Member)` tells a dataset member, whose `spec` `dfo.fetch` takes, from a `DerivedMember`, whose `spec` is a `DerivedSpec`.
- Each `Root` of a derived member names the rendering the recipe read it in, and `groupby`, a `Groupby` of `by`, `op` and `levels`, when the recipe read it summed, as a breakdown or a sum over StatVars does. The ref keeps it through `to_json`, `from_json` and `data.save`.
- `dfo.pin(data)` keeps a dataset's versions fetchable with no time limit.
- `dfo.cards` stores `line`, `bar`, `table`, `stat` and `source` cards of a Dataset. `stat(change="percent")` is a percentage where 25.0 is a 25% rise.
- `dfo.share(cards, latest=...)` publishes cards at a public URL that follows new data or keeps today's versions, and returns its `shw_` write token. `replace=`, `dfo.snapshot` and `dfo.unshare` change it with the token, and `dfo.history` lists what each slot served.
- `dfo.fetch(share, slot=..., as_of=...)` returns the data a share's slot shows, or showed on a date. A slot whose version lists no frame-layout file, as a default fetch leaves it, reads the file the version's file selector renders from its stored frame.
